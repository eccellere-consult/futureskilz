# FutureSkilz Skill Shot Instructional Design Skill

## 1. Mission

Convert expert knowledge and approved learning sources into short, high-value learning experiences that help adults **understand, apply, practise and transfer** a professional skill to work.

A Skill Shot is not merely a short video. It is a deliberately designed learning unit that teaches one principal capability through a clear explanation, a case or example, guided application, learner practice and a practical takeaway.

The platform serves:
- **College graduates and new joiners** who need workplace orientation, foundational concepts and role readiness.
- **Working professionals** who need to apply tools, improve performance and expand functional expertise.
- **Professionals preparing for the next level** who need judgement, problem solving, leadership and cross-functional capability.

Keep core knowledge stable where appropriate, but adapt context, scaffolding, complexity, practice and proficiency expectations to the learner.

## 2. Inputs

Accept any combination of:
- Expert interview transcripts, session summaries and career/role information.
- Approved documents, PDFs, presentations, spreadsheets, templates, images and other supported uploads.
- Existing `skill.md` files or structured knowledge packages.
- Industry, function, process, role and competency information.
- Target learner persona, proficiency, learning goal and expected job task.
- Source permissions, confidentiality restrictions, expert corrections and attribution requirements.

If essential information is missing, proceed with supported content and record the gap. Do not fabricate facts, quotations, company details, metrics, case outcomes or expert experience.

## 3. Core instructional principles

### 3.1 Start with a real need
Begin with a workplace problem, decision, task, dilemma, mistake or desired outcome. Establish why the skill matters before explaining theory.

### 3.2 Define an observable outcome
Use a specific action verb. Examples:
- Explain the difference between a symptom and a root cause.
- Build a basic process map from a sequence of activities.
- Calculate a defined KPI using supplied data.
- Compare two options using a decision framework.
- Conduct a structured feedback conversation.

Avoid vague objectives such as “understand quality” unless observable evidence is defined.

### 3.3 Explain simply, then add precision
Use Feynman-style explanation:
1. Explain the idea in plain language.
2. Give a familiar analogy or concrete example when useful.
3. Introduce the accepted technical term.
4. Explain the logic, boundaries and limitations.
5. Check whether the learner can explain or use the idea.

Do not oversimplify to the point of making the concept inaccurate.

### 3.4 Demonstrate before independent performance
Use worked examples, annotated decisions, step-by-step demonstrations or model dialogues. Then give the learner a new but related problem to attempt.

### 3.5 Require active thinking
Include at least one purposeful learner interaction where feasible: predict an outcome, choose an action, diagnose a problem, recall a step, explain a reason or complete a small task. Provide thinking time and explanatory feedback.

### 3.6 Connect to work
Close with a checklist, decision rule, practice task, template, reflection or action the learner can use in a realistic setting.

### 3.7 Build a coherent curriculum
Link each Skill Shot to its parent skill, related skills, prerequisites, follow-on lessons and intended learning path. Avoid disconnected videos.

### 3.8 Respect adult learners
Treat learners as capable adults. Use relevant work contexts, acknowledge prior experience, make the value explicit, allow appropriate choice and avoid patronizing language.

## 4. Choose the teaching pattern

Select the pattern that best fits the learning objective. Combine patterns when helpful; do not force every topic into an identical format.

### Pattern A — Case-based learning
Best for strategy, business analysis, finance, management and decisions.

Structure: case context → decision/problem → concept or model → application to case → alternatives and trade-offs → learner challenge → takeaway.

### Pattern B — Demonstration and guided practice
Best for software, spreadsheets, tools, operational procedures and quality methods.

Structure: task and desired output → prerequisites → instructor demonstration → explanation of decisions → common errors → learner attempt → checklist.

### Pattern C — Scenario and role-play
Best for communication, negotiation, leadership, customer service and conflict management.

Structure: context and roles → difficult moment → response options → model dialogue → consequences → learner choice or rehearsal → debrief.

### Pattern D — Expert judgement and tacit knowledge
Best for troubleshooting, leadership, advanced practice and lessons from senior professionals.

Structure: real experience → decision point → what an expert noticed → options and trade-offs → action and outcome → transferable lesson → boundaries and caveats.

### Pattern E — Concept, analogy and worked example
Best for foundational concepts, frameworks, formulas and unfamiliar terminology.

Structure: question → plain-language explanation → analogy or visual → formal model → worked example → new practice problem → summary.

### Pattern F — Practice and feedback
Best when a skill requires repetition.

Structure: task → attempt → feedback against criteria → corrected example → second attempt or reflection → transfer plan.

## 5. Default Skill Shot structure

Target **5–10 minutes**. Use approximately 8 minutes by default unless the complexity or task requires another duration. Timings are flexible.

1. **Hook and workplace context — 30–60 seconds**
   - Present a credible situation, case, problem or decision.
   - Make the stakes clear.
   - Ask a question the lesson will answer.

2. **Learning outcome — 15–30 seconds**
   - State what the learner will be able to do.
   - Connect it to a job task or professional responsibility.

3. **Core concept — 60–120 seconds**
   - Define the concept in simple language.
   - Explain why it works and when to use it.
   - Introduce necessary terminology and framework.

4. **Method or demonstration — 60–120 seconds**
   - Show steps, inputs, decisions, outputs and checks.
   - Use a worked example, annotated visual, template, process map or dialogue.

5. **Application to the case — 60–150 seconds**
   - Return to the opening context.
   - Apply the method step by step.
   - Explain the reasoning and trade-offs.
   - Do not claim a result that the source evidence does not establish.

6. **Learner challenge — 30–60 seconds**
   - Ask one useful question, decision or mini-task.
   - Allow a short thinking pause.
   - Reveal the answer or model response with an explanation.

7. **Summary and transfer — 20–45 seconds**
   - Reinforce 2–4 key takeaways.
   - Give a workplace action, checklist or reflection.
   - Preview the next related Skill Shot.

Adjust timing rather than rushing. If a topic cannot be taught meaningfully in 10 minutes, split it into connected Skill Shots. Do not overload a lesson with unrelated objectives.

## 6. Content design rules

### One lesson, one principal outcome
A lesson may introduce supporting ideas, but it should have one main capability or task. Split unrelated topics into separate lessons.

### Case quality
A useful case contains enough context for the learner to reason: situation, objective, constraints, relevant facts/data and a decision or task. Keep it proportionate to the lesson duration.

Label fictional or composite cases as illustrative. For real cases, check source reliability, confidentiality and permission.

### Model and tool explanation
When introducing a framework, tool or model, cover the relevant items:
- What it is.
- What problem it helps solve.
- When to use it and when not to use it.
- Required inputs or prerequisites.
- How to apply it, step by step.
- How to interpret the output.
- Common errors, limitations and risks.
- A case or example showing the method in action.

Do not mechanically include every item when it does not serve the learning objective.

### Worked examples
Show the thinking process, not only the final answer. Explain why a step is taken, what evidence is used, which alternatives are rejected and how the learner can check the result.

### Knowledge checks
Prefer application-oriented questions over trivia. Provide feedback that explains the reasoning. Distractors should reflect plausible misconceptions, not trick wording.

### Accessibility and cognitive load
- Keep on-screen text concise.
- Use clear headings, readable visuals and one principal idea per scene.
- Provide captions and a transcript where supported.
- Describe important visual information in narration or accessible text.
- Avoid unnecessary animations, jargon and decorative elements.
- Do not display a long paragraph while the avatar reads the same paragraph aloud.

## 7. AI avatar coach requirements

The avatar is a guide and coach, not merely a talking head.

It should:
- Introduce the case and learning outcome.
- Explain concepts conversationally.
- Guide attention to diagrams, evidence and decision points.
- Demonstrate reasoning and practical methods.
- Ask the learner to predict, choose, recall or apply.
- Pause at appropriate points for thinking.
- Explain why an answer is effective or weak.
- Connect the lesson to prior and upcoming lessons.
- Use respectful, adult-to-adult language.

The avatar must not claim to be the real expert unless it is actually that expert and the representation is authorized. Disclose AI-generated narration or likeness where applicable. Use an expert's name, voice, likeness and story only within agreed permissions.

## 9. Source-to-learning workflow

### Step 1 — Inventory
List sources, file types, source owners, versions, rights restrictions and processing status. Preserve originals.

### Step 2 — Extract and structure knowledge
Extract concepts, facts, methods, procedures, examples, stories, KPIs, tools and lessons. For interview material, preserve the expert's meaning and distinguish personal recollection from independently verified fact.

### Step 3 — Identify the capability
Ask:
- What should the learner be able to do?
- In which job or real-world situation is this needed?
- What knowledge, decisions and actions enable that performance?
- What evidence would demonstrate success?

### Step 4 — Map knowledge to learning outcomes
Group material into candidate Skill Shots. Avoid one video per page or slide. Split content by meaningful capability, not source length.

### Step 5 — Select teaching pattern
Choose the pattern in Section 4 based on the type of capability and learner level.

### Step 6 — Draft blueprint and script
Create the metadata, learning outcome, case, explanation, method, application, practice and transfer task. Estimate spoken duration from the actual script and planned pauses; do not rely on a title or word count alone.

### Step 7 — Validate source fidelity
Check each factual claim, numerical value, quotation, expert story and process step against its source. Link claims to source pages, slides, transcript segments or timestamps where possible.

### Step 8 — Generate scenes
Create concise scene-by-scene HTML/visual instructions, avatar narration, captions and interactions. Visuals should support learning, not simply decorate the screen.

### Step 9 — Review and revise
Review instructional quality, accuracy, rights, confidentiality, accessibility, timing and clarity. Request expert review where the lesson relies on their experience or specialist judgement.

### Step 10 — Publish and connect
Version the approved lesson. Link it to its skill, competencies, prerequisites, assessments and learning paths. Preserve attribution and source references.

## 10. Build Skill Sets and learning paths

Use this hierarchy:

1. **Skill Shot:** one focused learning outcome, usually 5–10 minutes.
2. **Skill Set:** several related Skill Shots that together support a meaningful task or sub-capability.
3. **Capability Module:** multiple Skill Sets that build a broader functional or professional capability.
4. **Role or Domain Learning Path:** an ordered or adaptive collection of capability modules, practice and assessment.

For each connection, specify why the next lesson is relevant, any prerequisite and what the learner should be able to do after completing the sequence.

A typical sequence might be:
- Industry and business context.
- Function and role expectations.
- Core concepts and methods.
- Tools and process execution.
- Worked examples and guided practice.
- Exceptions and troubleshooting.
- Applied assessment or workplace assignment.
- Advanced judgement and continuous improvement.

Adapt this sequence to the job and learner. It is a guide, not a mandatory template.

## 11. Learner-level adaptation

### Foundational / new joiner
- Explain terminology and context.
- Use familiar examples and fully worked solutions.
- Make steps explicit.
- Provide scaffolding and immediate feedback.
- Focus on safe, repeatable execution.

### Working professional
- Use realistic functional problems.
- Emphasize correct application, efficiency and diagnosis.
- Include common exceptions and competing priorities.
- Reduce unnecessary explanation of concepts already mastered.

### Advanced / next-level professional
- Use ambiguous, cross-functional or higher-stakes cases.
- Emphasize trade-offs, assumptions, uncertainty and judgement.
- Compare alternative approaches.
- Ask the learner to justify decisions and consider system-wide consequences.

Use diagnostic evidence where available. Do not infer proficiency solely from job title, years of experience or video completion.

## 12. Quality rubric

Score each category from 1 to 5. A lesson should normally score at least 4 on critical dimensions before publication.

1. **Relevance:** Is the job or learner need clear?
2. **Outcome clarity:** Is the expected performance observable?
3. **Accuracy:** Are facts, examples and methods correct and appropriately sourced?
4. **Explanation:** Is the concept clear without being misleading?
5. **Demonstration:** Can the learner see how to apply the method?
6. **Case integration:** Does the case reinforce the concept?
7. **Active learning:** Does the learner retrieve, decide, practise or apply?
8. **Transfer:** Is there a realistic next action?
9. **Pacing and cognitive load:** Is the lesson focused and appropriately timed?
10. **Media and accessibility:** Are visuals, narration, captions and controls usable?
11. **Source rights and privacy:** Are permissions and confidentiality handled?
12. **Curriculum fit:** Is the lesson connected to relevant skills and learning paths?

Do not compensate for a factual error or rights violation with a high average score. Critical failures block publication.

## 13. Measurement

Measure distinct levels of outcome:

- **Engagement:** starts, progress, completion, replay and supporting-material use.
- **Learning:** recall, explanation, scenario decisions, quiz performance and practical task quality.
- **Transfer:** application in realistic work, manager/mentor feedback where appropriate and evidence of improved task performance.
- **Usefulness:** learner ratings and comments about relevance and practical value.

Do not treat completion or high ratings alone as proof of competence. Use assessment appropriate to the learning outcome.

## 14. Source integrity, privacy and permissions

- Do not fabricate facts, metrics, quotations, case outcomes or expert claims.
- Label fictional/composite examples and AI-generated synthesis.
- Keep traceable links to source material where feasible.
- Flag contradictions, missing evidence and uncertain claims.
- Do not publish confidential employer or client information without permission.
- Confirm the right to use uploaded documents, templates, images and other third-party material.
- Obtain consent for use of a contributor's name, voice, likeness and interview-derived stories.
- Keep private interview content separate from approved published lessons.
- Record contributor/editor approval and content version.

## 15. Expected outputs

For each production request, generate the following as appropriate:

1. `skill_shot_blueprint.md` — complete instructional design and metadata.
2. `narration_script.md` — spoken script with avatar cues and pauses.
3. `scene_plan.md` — scene-by-scene visual and HTML instructions.
4. `knowledge_check.md` — questions, correct responses and explanatory feedback.
5. `source_map.md` or structured equivalent — claims linked to source references.
6. `review_checklist.md` — accuracy, instructional, accessibility, rights and approval checks.
7. `learning_path_entry.md` — prerequisites, related lessons and curriculum position.

If the user requests only a `skill.md`, return the canonical skill file and do not imply that videos or HTML have already been rendered.

## 16. Final response when executing this skill

Report:
- Sources processed.
- Intended learner and learning outcome.
- Teaching pattern selected and why.
- Skill Shots proposed or created.
- Estimated duration and required assets.
- Source gaps, factual uncertainties or rights issues.
- Quality-review status.
- Recommended related lessons and learning path.

Be explicit about what has been drafted versus reviewed, approved, rendered or published.
